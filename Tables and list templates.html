HTML Lists & Tables — Full Reference

Lists group related items. Tables display data in rows and columns. Both have accessibility rules that are easy to skip but matter a lot.

1. Unordered list — <ul>

Where used: Navigation menus, feature lists, ingredient lists — any items where ORDER doesn't matter.
When to use: When items could be reordered without changing meaning.
Why needed: Screen readers announce "list, 3 items" and let users jump between items — using plain <div>s loses that navigation entirely.
Default bullets
  • Nike Air Force 1
  • Adidas Ultraboost
  • Converse Chuck 70
<ul> <li>Nike Air Force 1</li> <li>Adidas Ultraboost</li> <li>Converse Chuck 70</li> </ul>

2. Ordered list — <ol>

Where used: Recipe steps, setup instructions, rankings/leaderboards — anything where SEQUENCE matters.
When to use: When reordering the items would break the meaning (step 3 before step 1 makes no sense).
Why needed: Browsers auto-number these for you, and the type/start/reversed attributes give you numbering control without manually typing "1. 2. 3."
Default (decimal) numbering
  1. Preheat the oven
  2. Mix the batter
  3. Bake for 25 minutes
<ol> <li>Preheat the oven</li> <li>Mix the batter</li> <li>Bake for 25 minutes</li> </ol>
type="A" + start="3" + reversed
  1. Third place
  2. Second place
  3. First place
<ol type="A" start="3" reversed> <li>Third place</li> <li>Second place</li> <li>First place</li> </ol> /* type: 1 | A | a | I | i start: number to begin counting from reversed: counts DOWN instead of up */

3. Nested lists

Where used: Multi-level navigation menus, table of contents, category/sub-category listings.
When to use: When items have a parent-child relationship (a category with sub-items).
Why needed: Nesting the <ul> INSIDE the <li> (not after it) is what creates real hierarchy — screen readers announce the nesting level.
A sub-list nested inside a list item
  • Men's Shoes
    • Running
    • Basketball
  • Women's Shoes
<ul> <li>Men's Shoes <ul> <li>Running</li> <li>Basketball</li> </ul> </li> <li>Women's Shoes</li> </ul> /* the inner <ul> goes INSIDE the <li>, not as a sibling after it */

4. Description list — <dl> <dt> <dd>

Where used: FAQs, glossary/term definitions, product spec sheets (label: value pairs).
When to use: When you have a term/label paired with its description/value — not just a plain list of items.
Why needed: This is the semantically correct tag for label-value pairs — more meaningful than a <ul> with bold text pretending to be a label.
Term + description pairs
Material
Genuine leather upper
Warranty
6 months against manufacturing defects
<dl> <dt>Material</dt> <dd>Genuine leather upper</dd> <dt>Warranty</dt> <dd>6 months against manufacturing defects</dd> </dl> /* dl = description list, dt = term, dd = its description */

5. Custom list styling (removing bullets, custom markers)

Where used: Navigation menus (bullets removed), custom checkmarked feature lists, styled card-like list items.
When to use: When the DEFAULT bullet doesn't fit the design, but the semantic <ul>/<li> structure should stay (for accessibility).
Why needed: Removing bullets via CSS (list-style: none) keeps the semantic meaning for screen readers while giving full visual freedom — better than using <div>s.
list-style: none + custom card styling
  • ✓ Free shipping over ₱2,000
  • ✓ 7-day return policy
  • ✓ Cash on delivery available
ul { list-style: none; /* removes the bullet */ padding-left: 0; } li { background-color: #a5d8ff; padding: 6px 10px; border-radius: 4px; } /* still semantically a list — screen readers still announce "list, 3 items" */

6. Table basics — <table> <thead> <tbody> <tr> <th> <td>

Where used: Pricing comparison tables, order summaries, spec sheets, any tabular DATA (not for page layout — that's what Grid/Flexbox are for).
When to use: Only for actual tabular data with rows AND columns that relate to each other.
Why needed: thead/tbody let browsers/screen readers distinguish headers from data; th (vs td) is announced differently, telling users "this is a column/row label."
Basic structured table
ProductSizePrice
Nike Air Force 140₱4,995
Adidas Ultraboost41₱6,200
<table> <thead> <tr> <th>Product</th> <th>Size</th> <th>Price</th> </tr> </thead> <tbody> <tr> <td>Nike Air Force 1</td> <td>40</td> <td>₱4,995</td> </tr> </tbody> </table>

7. colspan & rowspan (merging cells)

Where used: Order summaries with a "Total" row spanning multiple columns, schedules with a cell spanning multiple time slots.
When to use: When one cell logically needs to cover the space of multiple columns or rows.
Why needed: Without this, you can't represent a "this label applies to 3 columns" relationship — the table would need extra empty cells instead.
colspan="2" merges the total row's label
Nike Air Force 1x1₱4,995
Adidas Ultraboostx1₱6,200
Total₱11,195
<tr> <td colspan="2">Total</td> <td>₱11,195</td> </tr> /* colspan="2" makes this cell take up the width of 2 normal columns */ <!-- rowspan works the same way, but vertically --> <td rowspan="2">Spans 2 rows</td>

8. caption (table title)

Where used: Any table that needs a title/description — especially when there are multiple tables on one page.
When to use: Whenever a heading-like label is needed for the table's purpose.
Why needed: Screen readers announce the caption when entering the table — much better than a plain <p> or <h3> floating above it with no programmatic link.
Table with a caption
Order #1042 — August 2026
ItemPrice
Nike Air Force 1₱4,995
<table> <caption>Order #1042 — August 2026</caption> <thead>...</thead> <tbody>...</tbody> </table>

9. scope attribute (table accessibility)

Where used: Any data table with headers on both the top row AND the left column (like a comparison matrix).
When to use: Whenever a <th> needs to clarify whether it labels a COLUMN or a ROW.
Why needed: Without scope, screen readers can only guess. scope="col" or scope="row" makes it explicit, so users navigating cell-by-cell hear the correct header.
Row headers using scope="row"
SizeStock
3912
405
<thead> <tr> <th scope="col">Size</th> <th scope="col">Stock</th> </tr> </thead> <tbody> <tr> <th scope="row">39</th> <td>12</td> </tr> </tbody>

10. Responsive tables (horizontal scroll wrapper)

Where used: Wide tables (many columns) viewed on narrow mobile screens.
When to use: Whenever a table is too wide to fit a phone screen without squishing every column unreadably small.
Why needed: Wrapping the table in a scrollable container lets the table keep its natural width — the user scrolls sideways instead of everything becoming unreadable.
Narrow box, wide table — scroll sideways to see it all
ProductSizeColorStockPrice
Air Force 140White12₱4,995
.table-scroll-wrapper { overflow-x: auto; } <div class="table-scroll-wrapper"> <table>...</table> </div> /* table keeps its natural width, wrapper scrolls instead of squishing columns */

All Tags & Attributes — Copy-Paste Cheat Sheet

<!-- ================= LISTS ================= -->

<ul>                      <!-- unordered list -->
  <li>Item</li>
</ul>

<ol type="1" start="1" reversed>  <!-- ordered list -->
  <li>Item</li>                  <!-- type: 1 | A | a | I | i -->
</ol>

<dl>                      <!-- description list -->
  <dt>Term</dt>
  <dd>Description</dd>
</dl>

/* CSS for lists */
ul, ol {
  list-style-type: disc;   /* disc | circle | square | decimal |
                               upper-roman | lower-alpha | none */
  list-style-position: outside; /* outside | inside */
  list-style: none;        /* shorthand to remove bullets entirely */
}


<!-- ================= TABLES ================= -->

<table>
  <caption>Table title</caption>

  <thead>
    <tr>
      <th scope="col">Column Header</th>
    </tr>
  </thead>

  <tbody>
    <tr>
      <th scope="row">Row Header</th>  <!-- optional -->
      <td>Data cell</td>
      <td colspan="2">Spans 2 columns</td>
      <td rowspan="2">Spans 2 rows</td>
    </tr>
  </tbody>

  <tfoot>
    <tr><td colspan="2">Total</td><td>₱0.00</td></tr>
  </tfoot>
</table>

/* CSS for tables */
table {
  width: 100%;
  border-collapse: collapse;  /* removes double borders between cells */
}
th, td {
  border: 1px solid #ccc;
  padding: 8px 12px;
  text-align: left;
}
th { background-color: #f1f3f5; }

/* zebra striping */
tbody tr:nth-child(even) { background-color: #f8f9fa; }

/* row hover highlight */
tbody tr:hover { background-color: #d0ebff; }

/* responsive wrapper for wide tables */
.table-scroll-wrapper { overflow-x: auto; }
